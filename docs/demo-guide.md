# NeighborMarket 限时演示与验收流程

这份流程用于在 5～10 分钟内复核项目的主要能力。它不是另一套测试，也不要求修改真实业务数据：界面展示负责说明用户路径，自动化报告负责证明难以稳定手工重现的并发、回滚和故障场景。

## 1. 演示前准备（不计时）

### 1.1 选择隔离环境

- 推荐使用一次性的 Compose 环境或专用本地演示库，不连接生产库。
- 只有显式启用 `demo` profile 才会创建 `neighbor_a`、`neighbor_b`；密码使用启动时设置的环境变量，不写入文档、仓库或命令历史。
- `scripts/demo/reset_demo_data.sql` 会清除目标库中的业务数据。仅在确认是演示库、完成备份后手工执行；普通演示不需要重置数据。
- AI 可以不配置。未配置时正好可验证手工定价降级，不应临时填入真实密钥。

完整启动和恢复步骤见 [Docker 与部署指南](deployment.md)，演示数据的危险边界见 [`scripts/demo/README.md`](../scripts/demo/README.md)。

### 1.2 两分钟预检

1. 打开应用首页，确认页面能加载。
2. 访问 `/actuator/health`，预期 HTTP 200 且响应包含 `{"status":"UP"}`。
3. 分别确认两个演示账号可以登录；密码是本次启动时设置的值，仓库中没有默认密码。
4. 准备普通窗口和无痕窗口，分别保持发布者与领取者会话，避免反复退出登录。
5. 打开 GitHub Actions 的 `main` 分支最新 CI，确认后端、前端、镜像构建和核心浏览器 E2E 均成功。历史证据见 [自动化测试报告](AUTOMATED_TEST_REPORT.md)，现场以 Actions 页面为准。

任一预检失败时，先停止计时并按部署指南排查，不在未知数据库上执行重置脚本。

## 2. 五分钟核心流程

### 0:00～0:35｜市场与筛选

使用发布者窗口登录 `neighbor_a`，进入“逛闲置”。展示名称搜索、分类、交易方式和状态筛选，以及图片、价格/方式、新鲜度、状态和地点。

验收点：列表来自后端数据；改变筛选后只接受最新请求结果，取消旧请求不显示成网络错误。

### 0:35～1:20｜发布与 AI 降级

进入“发布”，填写名称、描述、分类、交易方式、公共交接地点和未来时段。如果选择固定价格：

- AI 已配置时，可点击“AI 帮我估价”，说明结果只是辅助建议，不是实时成交价。
- AI 未配置、超时、限流或返回无效内容时，展示明确提示，然后手工填写价格并继续发布。

验收点：AI 失败不阻断核心发布路径；浏览器不接触供应商密钥、Prompt 或原始响应。

### 1:20～2:05｜领取者表达想要

在领取者窗口以 `neighbor_b` 登录，找到刚发布的物品，选择未来交接时段并点击“我想要”。如时间允许，可取消后再次申请。

验收点：同一用户与物品不会累积重复意向；旧时段或非可领取物品不能申请。

### 2:05～3:05｜发布者确认与交接

回到发布者窗口，在物品详情的意向名单中确认 `neighbor_b`。随后展示双方“我的”页面中的交接卡、公共地点、时间和待交接状态。

验收点：物品从可领取变为已预订；只产生一个有效交接。双方都可取消，取消后物品恢复可领取。

### 3:05～3:45｜留言与回复

领取者在尚未完成的物品详情留言，发布者进行一层回复。

验收点：只有发布者可回复；不允许回复一条回复；完成后历史留言仍可读但不可新增。

### 3:45～4:20｜完成与归档

发布者在交接卡点击“标记已送出”，再打开“我的”页面。

验收点：物品和交接均为完成状态，记录进入已完成历史，不删除意向、交接或时段历史。

### 4:20～5:00｜看板与工程证据

打开“社区数据”，展示本月发布、本月成交、当前在售，以及最快完成和最想要但尚未成交。最后展示健康端点和最新成功 CI。

验收点：看板由数据库聚合生成；健康检查覆盖应用和数据库连接；CI 包含真实 MySQL、浏览器闭环和容器重启后的持久性检查。

## 3. 十分钟扩展复核

核心流程之后，如有额外五分钟，按以下顺序补充：

1. **版本化编辑**：发布者编辑一个仍为可领取且没有等待意向的物品；旧版本请求返回 409，不能覆盖新值。
2. **编辑/申请竞争**：不要靠人工同时点击下结论。打开 [状态机与并发时序](STATE_MACHINE_AND_CONCURRENCY.md) 和 [自动化测试报告](AUTOMATED_TEST_REPORT.md)，说明两条路径按同一物品行锁顺序串行。
3. **多人确认竞争**：展示真实 MySQL 并发测试证据；两个领取者竞争时只能有一个成功，失败方无残留交接。
4. **取消/完成竞争与回滚**：展示测试证明最终状态只能是合法组合，中途异常会回滚物品字段、交接和时段变更。
5. **图片安全**：上传允许格式和大小内的图片，说明服务端会校验真实格式、尺寸并移除元数据；受管图片使用不可变 URL。

并发结论以真实 MySQL 自动化测试为准。手工双击只能帮助观察界面防重，不能证明事务、锁或约束正确。

## 4. 失败时的替代路径

| 现场情况 | 继续方式 | 能证明什么 | 不能声称什么 |
| --- | --- | --- | --- |
| AI 未配置或供应商不可用 | 展示错误提示，手工填写价格并发布 | 核心流程不依赖 AI | AI 当前可用或结果准确 |
| 演示库已有脏数据 | 换用新名称发布，或改用隔离环境 | 新增业务路径 | 既有数据状态正确 |
| 浏览器现场流程失败 | 保留错误与请求 ID，展示最近成功 E2E 报告 | 已有自动化基线 | 当前环境已通过 |
| 无法访问 GitHub | 展示本地自动化报告并注明 CI 未现场核验 | 最近记录的验证范围 | 最新远端运行成功 |
| 并发场景难以手工同步 | 展示时序文档和真实 MySQL 测试 | 锁、条件更新和最终状态断言 | 人工点击复现了竞争 |

## 5. 结束检查

- 不展示或复制密码、Cookie、CSRF token、数据库口令和 AI 密钥。
- 不在生产库运行演示数据脚本，也不为演示修改历史数据。
- 现场创建的数据如需清理，按所用隔离环境的生命周期处理；不要删除共享环境中的他人记录。
- 对未现场验证的能力使用“已有自动化证据”或“本次未验证”，不要表述为刚刚通过。

演示完成的最低标准是：核心业务闭环能够复核，AI 失败时仍可发布，并发与回滚有真实 MySQL 证据，健康端点可访问，最新 CI 状态已明确。
