# 业务缓存场景决策记录

> 决策编号：NM-F-05  
> 日期：2026-10-19  
> 结论：当前不缓存物品详情、市场搜索结果或社区看板；保留图片的不可变 HTTP 缓存。

## 1. 决策边界

本记录评估应用层或 Redis 业务缓存，不把数据库 Buffer Pool、浏览器静态资源缓存和构建依赖缓存混为一谈。缓存不能替代 SQL、索引、分页和查询模型优化，也不能削弱物品版本、状态机和权限检查。

## 2. 已有性能证据

- 市场列表和“我的发布”已经从随结果数增长的 N+1 查询收敛为固定 2 条和 3 条 SQL。
- 意向、交接、留言和看板读取也已收敛为固定查询数。
- 3,000 件物品基线下普通列表与详情相关读取为毫秒级，没有数据库压力证据。
- 30,000 件 AVAILABLE 物品下，LIKE 搜索的高命中首页约为毫秒级；唯一命中和无命中的列表/count 在本机约为数十毫秒。瓶颈是任意子串语义导致的线性扫描，不是相同查询被重复执行的证据。
- 当前只有一个后端实例，且没有生产请求量、缓存命中率或数据库饱和度数据。

这些数据只用于同环境决策，不作为生产 SLA。

## 3. 候选场景逐项评估

| 场景 | 潜在命中率 | 一致性与失效范围 | 当前决策 |
| --- | --- | --- | --- |
| 热点物品详情 | 尚无真实热点分布；本地演示数据不能代表生产访问 | 发布者可编辑物品、替换图片和时段；申请、确认、交接会改变状态和版本。还需区分公开字段与登录用户权限 | 不缓存。数据库主键读取成本低，失效复杂度大于已证明收益 |
| 市场列表/搜索 | 关键词、分类、交易方式、状态、页码和排序组合形成高基数键；无重复率数据 | 任一物品发布、编辑、图片变化、预留、完成或重新上架都可能影响多个列表、count 和页边界，难以精确失效 | 不缓存。优先按既定阈值评估 MySQL ngram FULLTEXT |
| 社区看板 | 所有人读取同一聚合，理论上可复用，但当前查询已有索引和固定上界 | 发布、申请、确认和完成都会改变统计或排行；TTL 会让“真实记录”看板短期陈旧 | 暂不缓存。只有指标证明聚合持续形成数据库压力时再评估短 TTL |
| 我的页面、权限和状态 | 用户维度导致键分散，命中率未知 | 与当前用户、物品版本、意向及交接状态强相关；陈旧数据可能误导操作，写入仍必须回库校验 | 明确不缓存 |
| 物品图片 | URL 在替换后生成新不可变键 | 旧 URL 内容不覆盖，数据库原子切换引用；删除采用补偿和延迟清理语义 | 继续采用现有一年 `public, immutable` HTTP 缓存，不引入 Redis |

## 4. 为什么缓存不能解决当前搜索问题

搜索结果缓存只有在相同的规范化查询、筛选、页码和数据版本被重复访问时才命中。当前没有这种访问分布证据。与此同时，任一可见物品变化都可能使许多搜索键失效；全量清空会降低命中率，精确反向索引又会引入额外状态和复杂度。

最坏搜索来自 `LIKE '%keyword%'` 的扫描。缓存第一次查询不会更快，也不能改善大量一次性或低频关键词。达到容量阈值后，应先调整搜索语义并评估 MySQL ngram FULLTEXT；只有确认的重复热点仍造成压力时，才讨论结果缓存。

## 5. 复评条件与采用门槛

出现下列证据后重新评估具体场景，而不是整体启用“通用缓存”：

1. 连续生产观测显示某个读取端点的 p95 超过目标，并且数据库 CPU、锁等待或查询吞吐确认它是瓶颈。
2. 已完成 SQL、索引、分页和查询模型优化，慢查询仍存在。
3. 真实请求分布证明候选键具有可观且稳定的重复率；上线前明确目标命中率，并能按指标验证。
4. 已列出所有写入路径、最大允许陈旧时间、失效策略、容量上限、淘汰策略和缓存不可用时的回源行为。
5. 测试覆盖写后读、状态转换、权限变化、并发失效和缓存故障；缓存不可用不得破坏核心发布与交接流程。

搜索仍沿用 NM-C-05 阈值：可搜索物品接近 100,000 级、搜索 p95 超过 200ms、数据库 CPU 明显升高，或产品接受分词/前缀语义时，先评估 MySQL ngram FULLTEXT。看板只有在真实聚合压力成立且业务接受明确 TTL 时，才可试验短时本地缓存；计划扩展多实例时必须同时重新评估一致性，不能默认沿用。

## 6. 最终决策

- NM-F-05 当前选择“否决引入业务缓存”，这是有性能、一致性、命中率和失效成本依据的完成结论。
- 保留现有图片不可变 HTTP 缓存，因为其内容寻址和替换新键使一致性边界清晰。
- 不新增 Redis、Spring Cache、缓存表或自制内存 Map。
- 下一步进行 NM-F-06 架构边界复核，确认没有真实需求时继续保持模块化单体。
