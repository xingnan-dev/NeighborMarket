## 4. 关键闭环证据

- 编辑只允许发布者操作 `AVAILABLE` 物品；请求版本过期、存在 `WAITING` 意向或状态变化时拒绝写入。
- 编辑与申请先锁定同一物品行并校验版本，真实 MySQL 竞争测试验证两者不能同时成功；失败事务不会留下部分字段或时段更新。
- 图片替换和删除复用编辑权限与版本约束；新文件失败补偿删除，旧受管文件只在数据库提交后清理。
- 发布页图片上传失败不会重复创建物品；编辑页图片失败不会丢失文字、价格、地点或时段表单。
- Playwright 使用发布者与领取者两个独立 Session，完成登录、发布、申请、确认、完成和归档闭环。
- 人工响应式验收发现的问题已形成代码修复并复验，而非只记录为已知缺陷。

## 5. 已知边界

- 核心 E2E 覆盖主要成功路径；编辑冲突、图片恶意输入、权限和故障补偿由服务、Web 和 MySQL 集成测试承担。
- 响应式证据来自本地真实 Chrome 的响应式视口与桌面窗口，不等同于覆盖所有实体设备、浏览器内核和系统字体组合。
- 图片首版仍是一件物品一张主图、本地独立卷存储；对象存储、多图、审核和 CDN 不在 Phase E 范围。
- 未配置真实 AI 服务，估价测试继续使用本地测试替身；手工发布路径不依赖 AI。
