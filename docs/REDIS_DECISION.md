# Redis 必要性决策记录

> 决策编号：NM-F-01
> 日期：2026-10-19
> 结论：当前不引入 Redis；满足复评条件后再决定是否采用。

## 1. 当前事实

| 维度 | 当前实现与证据 | 对 Redis 的含义 |
| --- | --- | --- |
| 部署实例 | `compose.yml` 只运行一个 Spring Boot 后端实例，没有负载均衡或水平扩容配置 | 不存在跨实例共享状态需求 |
| Session | Spring Security 使用容器内 HttpSession，登录会轮换 Session ID；生产 Cookie 安全边界已有测试 | 单实例下本地 Session 足够，Spring Session Redis 暂无收益 |
| AI 限流 | `PricingService` 以用户名为键，在单进程 `ConcurrentHashMap` 中执行60秒冷却；重复请求测试覆盖429 | 单实例可满足当前规则；重启或多实例时不保证全局严格限额 |
| AI 流量 | 本地 Compose 默认不配置 LLM；Phase D/E 验收均未调用真实 AI；当前没有生产调用量、成本或峰值数据 | 没有依据为未知流量部署共享限流存储 |
| 数据读取 | Phase C 已消除主要 N+1；3,000物品基线下普通页面查询为毫秒级，30,000物品最坏子串搜索为数十毫秒 | 当前瓶颈证据指向搜索语义与扫描，不是缺少通用缓存 |
| 一致性 | 物品、意向、交接、图片和时段均有频繁状态变化、版本校验和事务约束 | 缓存会新增失效与陈旧读取风险，不能替代 MySQL 一致性规则 |

## 2. 候选用途评估

### 2.1 共享 AI 限流

当前内存冷却在一个后端实例内是原子的，规则简单且已有测试。此时接入 Redis 会增加网络调用、序列化、连接池、健康监控和 Redis 故障降级，却不会提高单实例正确性。

如果后端扩展到两个或更多实例，或者付费 AI 要求“跨实例、跨重启都不能超额”的严格预算保护，再评估 Redis 原子计数/TTL。无论 Redis 是否可用，AI 失败都必须降级到手工填写价格，不能阻断发布。

### 2.2 Session 共享

当前只有一个后端实例，不需要共享 Session。只有确认采用多实例且不能使用可靠粘性会话时，才评估 Spring Session Redis。采用前必须验证登录、Session ID 轮换、CSRF、注销、过期、序列化兼容和 Redis 故障行为，不能仅添加依赖和配置。

### 2.3 业务缓存

- 市场列表和详情包含新鲜度、版本、状态、意向和交接变化，缓存失效面较大。
- 社区看板由真实业务记录聚合，当前查询已有索引和固定查询上界，没有生产延迟或数据库压力证据。
- 子串搜索最坏情况来自 `%keyword%` 扫描；Redis 结果缓存不能解决高基数关键词、分页和失效问题。达到既定阈值时应先评估 MySQL ngram FULLTEXT，而不是用缓存掩盖查询模型。
- 图片已经使用不可变 URL 与长期 HTTP 缓存，不需要 Redis 存放图片或文件元数据。

因此当前不缓存物品、搜索结果、看板或权限数据。

## 3. 运维成本

引入 Redis 至少意味着：新增生产服务与版本升级、连接与超时配置、内存上限和淘汰策略、持久化/备份取舍、监控告警、访问控制、网络隔离、故障演练，以及应用在 Redis 不可用时的降级语义。若承担 Session，还会把 Redis 故障扩大为登录态故障；若承担 AI 限流，则必须防止 Redis 故障误伤手工发布。

当前单实例面试展示部署没有足够收益抵消这些成本。

## 4. 复评触发条件

出现任一条件时重新执行本决策，而不是自动采用 Redis：

1. 后端计划扩展到两个或更多实例。
2. 多实例环境不能采用可靠粘性会话，且登录态必须无感跨实例。
3. 真实 AI 指标显示需要跨实例、跨重启的严格配额或成本上限；单实例近似冷却不再可接受。
4. 生产指标证明某个可安全失效的热点读取持续造成数据库压力，并已经先完成 SQL、索引和查询模型优化。
5. 已明确 Redis 不可用时 Session、限流和业务读取的降级/失败策略，并具备监控与恢复能力。

“技术栈展示”“可能以后会扩容”或“缓存通常更快”不构成采用条件。

## 5. 最终决策

- NM-F-01：VERIFIED，当前明确不引入 Redis。
- NM-F-03：继续保持条件阻塞；只有共享 AI 限流需求成立后才实施。
- NM-F-04：继续保持条件阻塞；只有多实例且需要共享 Session 后才实施。
- NM-F-02 可独立推进：先增加不含 Prompt/响应内容的 AI 结果、延迟、限流和失败分类指标，为未来复评提供真实数据。
- NM-F-05 继续逐项记录缓存否决/采用理由，不以引入缓存作为完成标准。
